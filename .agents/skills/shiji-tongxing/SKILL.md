# 市集同行 · 开发技能

## 平台定位

地摊经济 SaaS 撮合平台，连接四方角色：

```
摊主(找场) ←→ 平台(撮合+履约+结算) ←→ 场地方(招商)
                    ↕              ↕
              推广大使(CPS)    管理单位(合规)
```

## 核心术语（必须遵守）

| 术语 | 定义 | 禁止混用 |
|------|------|---------|
| **集市** | 大厅内放置物品的区域 | 不要说"场地" |
| **场地** | 活动举办的物理地点 | 不要说"集市" |
| **账户** | 平台用户 | 不要说"账号" |
| **活动** | 实际开展的经营事件 | — |
| **摊位** | 活动中的最小经营单元 | — |
| **推广大使** | 联盟大厅中推广活动的用户 | — |

## 角色与权限

| 角色 | 能力 | 对应 RBAC |
|------|------|-----------|
| 摊主(stallholder) | 浏览活动、报名、缴费、经营复盘 | user |
| 场地方(venue_owner) | 发布场地、创建活动、管理招商 | venue_admin |
| 运营方(platform_admin) | 全平台管理、审核、数据看板 | admin |
| 推广大使(promoter) | 接推广任务、分享绑定、佣金提现 | promoter |

## 四层收入模型

1. **摊位租金** — 固定租金 或 营业额抽成
2. **场地分成** — 场地方收益比例抽成（如 4%-6%）
3. **会员费** — 认证会员标识 + 优先权 + 积分抵扣
4. **推广佣金** — CPS 分销（固定金额 / 比例佣金）

## 开发原则

### 后端
- Fastify + TypeScript + Prisma，复用 MyWork RBAC 底座
- 所有涉及金额的字段用整数（分），不用浮点数
- 状态流转必须有严格校验，不允许跳跃

### 前端
- 小程序端默认 WeChat 原生，禁止引入第三方 UI 框架
- Web 管理后台用 React + Vite + Tailwind CSS
- 所有用户输入必须有表单校验

### 数据处理
- 时间统一存 UTC，展示时转北京时间
- 手机号、身份证号加密存储
- 交易流水不可删除，只能标记作废

## 会员权益体系

| 模块 | 权益 |
|------|------|
| 优先权 | 免费活动优先报名(24h预热)、报名费免费、押金9折、佣金减免2%、入场费9.5折 |
| 全程保障 | 实时通知、落选优先递补、纠纷协调 |
| 认证标识 | 主页标识、平台工具免费用、积分体系(100积分=1元) |

## 联盟大厅(CPS)核心链路

```
推广任务发布 → 用户报名 → 审核通过 → 分享绑定(追踪码) → 转化计佣 → 结算 → 钱包提现
```

防羊毛机制：人数上限、集赞门槛(≥20-30)、保留≥48h、截图时效(2h)、48h复查

## AI 重建七阶段

| Phase | 内容 | 依赖 |
|-------|------|------|
| P1 数据底座 | Schema + Seed + 基础 API | MyWork RBAC |
| P2 活动管理 | CRUD + 状态流转 + 审核 | P1 |

| P4 联盟大厅 | CPS 推广 + 追踪 + 佣金 | P3 |
| P5 会员积分 | 等级权益 + 积分流水 | P3 |
| P6 小程序端 | 摊主/场地方双端 | P2-P5 |
| P7 数据看板 | 图表 + 趋势 + 导出 | P2-P5 |
