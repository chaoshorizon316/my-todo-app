## 一、产品定义

### 一句话

> **把家长从微信里"人肉拆任务"的劳动中解放出来，让孩子看到的不再是指令，而是有理由的行动。**

### 产品是什么

一个**带状态的消息系统**。家长端输入 → AI 拆解并补上"为什么" → 儿童端展示为可执行的任务卡片 → 孩子完成确认 → 家长端实时同步。

不是任务管理系统，不是教育产品，不是 Trello/Asana 的家庭版。

### 核心差异化

**每个任务都带"why"。** 所有竞品解决的是"任务信息传递"，没有一个解决"让孩子理解为什么做"。

### 核心价值

| 对家长 | 对孩子 |
|--------|--------|
| 10 秒布置完作业，不用再"人肉 AI" | 知道做什么，也知道为什么做 |
| 不开口催促，任务自然到达孩子设备 | 做完一个勾一个，感觉到自己"做到了" |
| 下班路上看一眼，全绿了就安心 | 学习是自己的事，不是妈妈的事 |

### 产品气质

> 「接住」是一个安静的产品。不喧哗——没有排行榜、没有弹窗、没有焦虑文案。它只是接住那些容易掉落的任务——从微信群的混乱消息里把它们捡起来，补上一个"为什么"，轻轻放在孩子面前。然后退后一步。让孩子自己走过去。

## 二、用户与场景

### 目标用户

- **核心家长**：小学生家长（1-6 年级），双职工，每天靠QQ群、微信群接收作业
- **核心儿童**：能识字、能操作 iPad 的小学生，或能操作语音播放功能的小学生
- **V1 范围**：一个家庭单元，支持 1 儿童 : N 家长（爸爸、妈妈均可绑定）

### 核心场景

```
17:30  妈妈在公司，微信群里老师发了一段 300 字的消息
       → 复制，打开「接住」，粘贴
       → AI 拆成 6 个任务 + 补上解释 + 标记学科 + 识别重要度
       → 扫一眼，点"发送"
       → 孩子 iPad 上收到

17:35  孩子打开 iPad，看到 6 张任务卡片（按学科分组）
       → 点开第一张"背诵日积月累"（⚠ 重要标记）
       → 看到 "明天随堂测试会考这个，背熟了明天就不慌"
       → 不认识的字点 🔊 语音播报
       → 点"开始，我准备好了"，开始背

17:55  背完了，点"已完成"
       → 弹出 "要不要告诉妈妈？"
       → 点"告诉妈妈"
       → 妈妈手机上弹出推送："小宝背完了日积月累"

18:45  下班路上，妈妈打开 APP
       → 6 个任务 6 个勾，全绿
       → 安心
       → 回家仅需把重点内容挑选出来进行抽查
```

## 四、家长端详细设计

### 4.1 Landing 页（P0）

- 产品名「接住」+ emoji
- 3 个核心功能点：智能拆解、每个任务有"为什么"、实时同步
- "进入"按钮
- 底部提示"首次使用？先绑定孩子设备 →"（引导到扫码）

### 4.2 任务输入区（P0）

**尺寸**：最小高度 180px（约占手机屏幕 1/4），可滚动。

**三种输入方式**：
1. **粘贴**：将微信复制的文字 paste 进文本区
2. **语音**：点击 🎤 按钮，调系统语音识别，转文字后填入
3. **截图**：V1 可选（P2），分享微信截图进来

**按钮**：
- 主按钮「✨ 智能识别」：将文本发送到 AI 接口进行拆解
- 次按钮「🎤 语音」：触发语音录入

**交互**：点击文本区任意位置跳转到 AI 拆解预览页。

### 4.3 AI 拆解预览页（P0）

**结构**：
1. 顶部：原始消息展示区（暖灰背景，展示识别到的原文）
2. 操作栏：🔄 重新拆解 / ＋ 新增任务 / 已识别 N 个任务
3. 任务列表：每条任务卡片包含
   - ☑ 勾选框（默认全选）
   - 学科标签（语文/数学/英语，带颜色）
   - ⚠ 重要标记（如识别到"明天测试""考试"）
   - 任务内容
   - 💬 AI 生成的"为什么"（灰色 = AI 建议，可点编辑改为黑色）
   - 时间标签 + 来源老师（如"今日必须完成 · 语文老师"）
   - ✏️ 编辑按钮：展开内联编辑（修改内容、why、学科、时间标签、重要度）
   - ✕ 删除按钮：移除此任务
4. 本周/长期任务区（折叠展示）
5. 底部双按钮：「返回修改」/「确认并发送」

**编辑模式字段**：
- 任务内容（text input）
- why 说明（text input）
- 学科（select: 从学科列表选择）
- 时间标签（select: 今日必须完成 / 本周完成 / 长期积累）
- 重要度（checkbox: 是否标记为重要）

**"新增任务"行为**：在任务列表末尾插入一条空白任务，默认学科=语文，自动进入编辑模式。

**"重新拆解"行为**：重新调用 AI 接口（非覆盖原结果，而是在下方生成新结果供对比？V1 直接替换）。

### 4.4 任务主列表（P0）

**分组逻辑**：按学科分组（语文 → 数学 → 英语 → 其他），每组有学科标题头（`📖 语文`）。

**三个时间区域**：
- **今日任务**：按学科分组，带状态标识（● 已完成 / ◉ 进行中 / ○ 未开始），右上角显示完成进度 "3/6 已完成"
- **本周**：本周内需完成的任务
- **长期积累**：长期持续任务

**状态实时同步**：孩子在儿童端的操作 → WebSocket 推送 → 家长端状态即时更新。

### 4.5 足迹页（P1）

**统计指标**：
- **完成率**（非准时率）：已完成任务数 / 总任务数
- 完成件数统计
- 一句话总结（≤20 字）

**时间段筛选**：
- 本周 / 上周 / 本月 / 上月 / 今年 / 去年
- 切换后统计数据联动变化

**日历视图**：
- 月历网格，每天标记完成状态：
  - 绿色 `cal-all-done` = 当日全完成
  - 橙色 `cal-partial` = 当日部分完成
  - 灰色 `cal-none` = 当日未完成
- 今天用边框高亮（不覆盖状态色）
- 点击某天 → 弹出底部面板（modal sheet），展示当日任务清单（已完成/未完成分别标记）

**V1 不做**：图表、雷达图、详细报告。

### 4.6 我的页（P0/P1）

**孩子信息**：
- 性别选择：👦 男孩·蓝色主题 / 👧 女孩·粉色主题
- 卡通主题：🚀 太空 / 🦕 恐龙 / 🦄 独角兽 / 🐱 小猫
- 切换后儿童端即时生效

**学科管理**：
- 显示当前学科列表（带颜色标签）
- 支持增删（至少保留 1 个）
- 默认：语文、数学、英语

**绑定管理**：
- 已绑定列表：显示孩子名、称呼、角色（主管理员/家长）、当前设备标识
- 主管理员：可"+ 邀请"其他家长（生成邀请二维码）
- 其他家长：可"解除"绑定
- "＋ 添加绑定"按钮 → 跳转扫码页

## 五、儿童端详细设计

### 5.1 设计原则

1. **这是孩子的领地**，不是家长的监控屏
2. **每个任务都有"why"**
3. **完成是自愿的**，不是被监控的
4. **只和自己比**

### 5.2 Landing 页（P0）

- 欢迎语 + 3 个功能点（孩子视角）
- "我准备好了！"按钮
- 底部"📷 扫描家长二维码绑定"入口

### 5.3 任务卡片流（P0）

**结构**：
- 顶部问候语：`⛅ 下午好，小宝`（emoji 随主题变化）
- 统计行："今天有 6 件事，你已经完成了 1 件 ✨"
- 右上角 📷 扫码按钮
- 学科筛选条：全部 / 语文 / 数学 / 英语（点击筛选）
- 学科分组标题：`📖 语文`（带学科色）
- 任务卡片：
  - emoji + 学科标签 + ⚠ 重要标记
  - 任务名 + 副标题（如有）
  - 💬 why 说明
  - 🖼️ 图片（如有，如看图描述任务）
  - 时间标签 + 来源（如"今日必须完成 · 语文老师"）
  - 🔊 TTS 语音播报按钮（卡片右侧）
  - "开始"按钮（待完成）/ "继续做"按钮（进行中，主题色浅底）
- 已完成卡片折叠为单行淡色展示

**排序**：
- 先按学科分组（学科顺序与家长端一致）
- 组内：未完成和进行中在上，已完成折叠在下

### 5.4 任务进行中（P0）

- 大号 emoji
- 学科标签 + ⚠ 重要标记
- 任务全名 + 副标题
- why 说明
- 图片（如有，居中展示）
- **计时器**：从点击"开始"起计时，大号等宽字体显示 MM:SS
- **"我完成了！"大按钮**：主操作
- **"先歇一会儿 · 不做了"**：小字（非按钮感），点击回到卡片流，任务保持"进行中"

### 5.5 告诉妈妈（P0）

- ✨ + "你完成了！"
- 任务名称
- **"📨 告诉妈妈"**：主要按钮（但可选！不强制）
- **"先不说"**：小字链接
- 无论选哪个，任务都标记为完成
- 选"告诉妈妈"→ 家长端推送通知

### 5.6 全部完成（P1）

- 庆祝 emoji（随卡通主题变化：🌟/🌈/🦴/🐾）
- "今天的事都做完了！N 件事，全部完成"
- "你比昨天快了 5 分钟"
- "去看看我的脚印 👣"按钮

### 5.7 我的脚印（P1）

**与家长端足迹对应，但面向孩子**：

- 时间段筛选：本周 / 上周 / 本月 / 上月 / 全部
- 日历视图（3 态标记，同家长端）
- 点击日期 → 弹出当日任务清单
- 统计数据（只和自己比）：
  - "这周你完成了 24 件事，比上周多了 3 件"
  - "有 15 件事是你自己想起来就做了，不用提醒"
- 文案全部用"你"（第二人称），不说"加油""继续努力"

## 六、AI 任务拆解引擎

### 6.1 输入 → 输出

```
输入：一段自然语言（粘贴的文字 / 语音转文字）

输出：
[
  {
    "content": "拼读课本79页双蓝线生字并口头组词",
    "why": "今天学的生字，读熟组词才算真正认识它们",
    "why_source": "ai_generated",
    "subject": "语文",
    "importance": false,
    "time_scope": "today",
    "time_label": "今日必须完成",
    "teacher_subject": "语文老师",
    "task_type": "single",
    "source": "teacher",
    "estimated_minutes": 15
  },
  { ... }
]
```

### 6.2 拆解维度（6 个维度）

| 维度 | 作用 | 推断方式 |
|------|------|---------|
| **动作单元** | 将一段话切为可执行的最小任务 | 按动作词切分："读""写""背""做""准备" |
| **学科归属** | 语文/数学/英语/其他 | 识别关键词："生字""课文"→语文；"计算""练习"→数学；"单词""朗读"→英语 |
| **时间归属** | today / week / ongoing | 显式时间词原样提取；无标记默认 today |
| **解释（why）** | 让孩子知道为什么做 | 显式原因翻译成儿童语言；无标记按任务类型推断 |
| **重要度** | 是否需要着重提示 | 识别"明天测验""考试""重点""竞赛"→标记为重要 |
| **任务关系** | single / choice / sequential | "或"→choice；"先…再…"→sequential |

### 6.3 学科识别规则

| 关键词 | 学科 |
|--------|------|
| 生字、课文、背诵、阅读、组词、造句、作文、摘抄、拼音、笔画 | 语文 |
| 计算、练习、口算、算式、应用题、几何 | 数学 |
| 单词、朗读、听写、拼写、英语、课文翻译 | 英语 |
| 其他 | 默认语文（可手动调整） |

### 6.4 重要度识别规则

| 信号词 | 标记 |
|--------|------|
| "明天测验""明天考试""明天听写""随堂测试""单元测试" | ⚠ 重要 |
| "重点""必考""必须掌握""期末" | ⚠ 重要 |
| 无以上信号 | 普通 |

### 6.5 why 生成规则

| 原文信号 | why 生成示例 |
|---------|------------|
| "明天随堂测试" | "明天随堂测试会考这个，背熟了明天就不慌啦" |
| "重点""复习""巩固" | "这是今天的重点知识，练一练就更熟了" |
| "课外阅读""积累" | "每天读一点课外书，脑子里就会有很多好东西，以后写作文就厉害了" |
| "预习" | "先看一看明天要学的内容，明天上课就更容易听懂" |
| 无任何标记 | 按学科推断："数学多练练，课堂上的知识就更扎实了" |

### 6.6 降级策略

```
LLM API 正常：
  粘贴文字 → 调 LLM → 返回结构化 JSON → 渲染预览卡片

LLM API 超时/失败：
  粘贴文字 → 降级提示："AI 暂时不可用，请手动分行输入"
           → 输入框变成多行文本域
           → 家长每行 = 一个任务
           → 不生成 why（可手动填写）
           → 核心闭环不受影响
```

## 七、数据模型

### 7.1 表结构（V1：6 张表）

```sql
-- 家庭
CREATE TABLE family (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name        VARCHAR(100),                    -- "小宝的家"
    child_name  VARCHAR(50),                     -- "小宝"
    child_gender VARCHAR(10) DEFAULT 'boy',      -- 'boy' | 'girl'
    cartoon_theme VARCHAR(20) DEFAULT 'rocket',  -- 'rocket'|'dino'|'unicorn'|'cat'
    created_at  TIMESTAMPTZ DEFAULT now()
);

-- 用户（家长或孩子，同属一个 family）
CREATE TABLE app_user (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    family_id   UUID REFERENCES family(id),
    role        VARCHAR(20) NOT NULL,            -- 'parent' | 'child'
    name        VARCHAR(50),
    nickname    VARCHAR(50),                     -- 家长对孩子的称呼（如"妈妈"）
    phone       VARCHAR(20) UNIQUE,
    is_admin    BOOLEAN DEFAULT false,           -- 是否主管理员
    created_at  TIMESTAMPTZ DEFAULT now()
);

-- 学科（每个家庭自定义）
CREATE TABLE subject (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    family_id   UUID REFERENCES family(id),
    name        VARCHAR(20) NOT NULL,            -- '语文'|'数学'|'英语'|...
    sort_order  INTEGER DEFAULT 0,
    color       VARCHAR(7),                      -- 自定义颜色（可选，有默认值）
    created_at  TIMESTAMPTZ DEFAULT now(),
    UNIQUE(family_id, name)
);

-- 任务（核心表）
CREATE TABLE task (
    id                UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    family_id         UUID REFERENCES family(id),
    content           TEXT NOT NULL,
    subtitle          VARCHAR(200),
    why               TEXT,                      -- 为什么要做
    why_source        VARCHAR(20) DEFAULT 'ai_generated', -- 'teacher_original'|'ai_generated'|'parent_edited'
    subject_id        UUID REFERENCES subject(id),
    importance        BOOLEAN DEFAULT false,      -- 是否重要
    time_scope        VARCHAR(20) DEFAULT 'today', -- 'today'|'week'|'ongoing'
    time_label        VARCHAR(30),                -- '今日必须完成'|'本周完成'|'长期积累'
    teacher_subject   VARCHAR(50),                -- '语文老师'|'数学老师'|...
    task_type         VARCHAR(20) DEFAULT 'single', -- 'single'|'choice'|'sequential'
    alternatives      JSONB,                     -- choice 类型时的备选项
    source            VARCHAR(20) DEFAULT 'teacher', -- 'teacher'|'mom'|'dad'
    estimated_minutes INTEGER,
    image_url         VARCHAR(500),              -- 任务附带的图片 URL
    status            VARCHAR(20) DEFAULT 'pending', -- 'pending'|'in_progress'|'done'
    assignee_id       UUID REFERENCES app_user(id),
    created_at        TIMESTAMPTZ DEFAULT now(),
    started_at        TIMESTAMPTZ,
    done_at           TIMESTAMPTZ,
    told_parent_at    TIMESTAMPTZ                -- 孩子主动告诉家长的时间
);

-- 家长对 AI 解释的编辑记录（用于学习偏好）
CREATE TABLE why_edit_log (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    task_id     UUID REFERENCES task(id),
    parent_id   UUID REFERENCES app_user(id),
    original    TEXT,
    edited      TEXT,
    created_at  TIMESTAMPTZ DEFAULT now()
);

-- 日历完成快照（每日汇总，供足迹查询）
CREATE TABLE daily_completion (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    family_id   UUID REFERENCES family(id),
    date        DATE NOT NULL,
    total_count INTEGER DEFAULT 0,
    done_count  INTEGER DEFAULT 0,
    status      VARCHAR(20) DEFAULT 'none',      -- 'all'|'partial'|'none'
    UNIQUE(family_id, date)
);
```

### 7.2 关键设计说明

- **学科不是全局枚举**：每个家庭在 `subject` 表中维护自己的学科列表，支持自定义
- **`why` 不是必填**：AI 不可用时家长可手动分行输入任务，why 可空
- **`daily_completion` 是派生表**：每天定时任务（或任务状态变更时）更新，避免足迹查询时实时聚合
- **图片用 URL**：V1 不建文件管理系统，图片上传到 OSS/S3，task 表只存 URL

```
家庭管理

  DELETE /api/families/:id/subjects/:sid    删除学科

任务管理

  PUT    /api/tasks/:id                      编辑任务内容
  DELETE /api/tasks/:id                      删除任务

足迹
  GET    /api/footprints?family_id=X&period=Y&date=Z  足迹统计数据
  GET    /api/footprints/calendar?family_id=X&year=Y&month=M  日历月度完成状态
  GET    /api/footprints/daily?family_id=X&date=Y    某日任务清单

绑定
  POST   /api/bindings/generate-qr          生成绑定二维码（儿童端调用）
  POST   /api/bindings/confirm              确认绑定（家长扫码后调用）
```

## 九、技术架构

```
家长手机 (Flutter / iOS+Android)
    │
    ├── HTTPS REST ──→  Spring Boot  ──→  PostgreSQL
    │                       │
    │                       ├── Redis (session + WebSocket pub/sub)
    │                       │
    │                       ├── LLM API (DeepSeek / GPT-4o-mini)
    │                       │   仅任务拆解时调用，一次请求
    │                       │
    │                       └── OSS/S3 (任务图片存储)
    │
    ├── WebSocket ──→ 实时状态同步
    │
    └── APNs/FCM ←── 离线推送通知

儿童 iPad (Flutter)
    │
    ├── HTTPS REST ──→  同上
    ├── WebSocket ──→   同上
    └── 本地 TTS ──→  AVSpeechSynthesizer / Android TTS
```

| 层 | 选型 | 理由 |
|----|------|------|
| 前端 | **Flutter** | 一套代码覆盖 iOS+Android 家长端 + iPad 儿童端 |
| 后端 | **Spring Boot** | 团队已有技术储备 |
| 数据库 | **PostgreSQL** | 6 张表，纯粹的关系型 CRUD |
| 缓存/WS | **Redis** | Session + WebSocket pub/sub |
| 推送 | **APNs + FCM** | 系统级推送，无需自建 |
| AI | **DeepSeek** 或 **GPT-4o-mini** | 选最便宜的，任务拆解不依赖强推理能力 |
| TTS | **系统原生** | iOS: AVSpeechSynthesizer, Android: TextToSpeech |
| 对象存储 | **OSS/S3** | 任务图片存储 |
| 部署 | **Docker + 阿里云 ECS** | 单机足够 V1 |

## 十、绑定与权限体系

### 10.1 绑定流程

```
场景 A：家长扫儿童（推荐）
  1. 家长打开「我的」→「添加绑定」
  2. 儿童端打开 📷 →「我的二维码」
  3. 家长扫描 → 输入称呼（如"妈妈"）→ 确认
  4. 绑定建立，儿童端收到通知

场景 B：儿童扫家长
  1. 儿童端 Landing 页点击「扫描家长二维码」
  2. 家长端「我的」→ 点击主管理员旁边"＋邀请"按钮 → 生成邀请二维码
  3. 儿童扫描 → 确认 → 绑定建立
```

### 10.2 权限模型

| 角色 | 权限 |
|------|------|
| **主管理员** | 创建/删除任务、管理绑定（邀请/解绑）、修改家庭设置（性别/主题/学科） |
| **普通家长** | 创建/删除任务、查看足迹 |
| **儿童** | 查看自己的任务、开始/完成/暂停任务、查看自己的脚印 |

- 第一个绑定的人自动成为主管理员
- 主管理员可转让
- 所有家长看到的任务和足迹是同一份数据

## 十二、V1 明确不做

| 不做 | 原因 |
|------|------|
| 积分/星星/金币/排行榜 | 外部激励破坏内在动机 |
| 专注模式/强制锁屏 | 需要系统级集成，V1 用简单全屏替代 |
| 家长远程催促按钮 | 变成压迫孩子的工具，违背信任设计 |
| 成长报告/数据图表 | V1 没有足够数据，做出来是假的 |
| 任务模板市场/分享 | 没有用户量 |
| 老师端 | 先验证家长-孩子链路 |
| 多孩子管理 | 先跑通一对一 |
| 定时提醒/番茄钟 | 让孩子和家长自己掌控节奏 |
| 离线同步/冲突处理 | V1 用户量不需要 |
| Android 平板 | iPad 先验证，碎片化太严重 |
| 社交媒体分享 | 家庭隐私优先 |
